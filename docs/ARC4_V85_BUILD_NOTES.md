## 1. Interpretation choices from the pre-I-stage review (fix agent, verbatim)

1. A.10.2 vs A.8/A.10.4: the D control does not say which rungs r_g(D:V2s) uses, or how a unit dropped by the cross-fit counts. The D control comes before the cross-fit in A.10, but λ is defined on K_{g,s}. Choice implemented, to be ratified before the I-stage: cross-fitted K_{g,s} where a cell survives, uncross-fitted K_g for a unit with no cell (stats-2).

2. A.5 vs A.10.2: A.5 makes any replay mismatch an Interruption, while A.10.2 counts 'every D confirmation exact' toward the D control, with one dated fix before Interruption (D). Choice: D's confirmations are judged by the D control; V2s mismatches are Interruptions.

3. §13.1 budget rule: 'project the cost' has no defined scope. Choice: the G1 core rows' emulated frames, from the I-stage mean V2s billed per run, with O_4 at 5x. The §13.1 worst case '0.68G, about 45 h' fits the G1 core alone. The cumulative 'up to the G1 verdict' reading gives a different n_O4 at U=10, n=6 (about 0.51G vs about 0.63G).

4. CENSORING-SENSITIVE (§8.2, §9, Part C): 'misses at 2x cap' does not say whose misses. A.11 NO-ROOM (b) uses only the comparator's. 'Drops one step' is undefined for FASTER-PARTIAL: the next label in Part C order, EARLY-RUNGS-ONLY, has another meaning. Choice: all misses of both arms at 8M; OBJECT-ROOM->KC-object, GO->KC-dev, FASTER-2X->FASTER-PARTIAL->NOT-SIGNIFICANT; non-claim labels never move.

5. B1 (§9, Part C) leaves these unspecified: the test behind 'p <= 0.025' (choice: one-sided exact sign-flip on unit log r_g, [9859, 2] above 16 units); the sealed instrument-line seeds (choice: V2s {9853, 9856} vs {9854, 9857}); the Page's L p-value method (choice: 20,000 within-unit permutations on [9859, 3]); the 'without near-siblings' line, which has no arm or contrast definition and is not implemented; and which percentile the interaction's 'lower bound > 0' means (choice: the 10th, like LB90; I unclipped).

6. Part B items 12-13 are scheduled 'during the I-stage', but §13.4 and A.13 make a dirty tree an Interruption, and the dirty flag covers ragnarok/ scripts/ tests/ including untracked files. Writing items 12-13 in this worktree while I-stage runs are in flight would void G1 (canfail-5). They must be written elsewhere and merged when no run is in flight.

7. Part B says the pre-I-stage code has 'their closures hashed', but names no record and no comparison. The new `v85_calib.py closures` writes craft_v6_out/v85/closures.json, and the I-stage verdict checks V2s and D against it when present. It must be regenerated after the last commit before the launch, and after the dated D fix. A.10.6's 'family code, development objects and κ' hashes must come from v85_objects (item 13) under the keys family_code, development_objects and kappa. FAM in v85_verdict.py names the family arms (K_S, F_S, X_S, T, S, GF, P_S, U_S, X4_S, X12_S, K_mine, F_M, X_on, X_frozen, DM_on, P_on, X4_on, X12_on); the item-12 module names must match them through canon().

Part B items 12-13 (family code and development objects) are written in a separate branch or worktree and merged into

## 3. Implementation choices declared by the build agents (verbatim)

### verdict-calib

- Bootstrap stream per contrast: default_rng([9805, crc32('<gate>:<arm>:<comparator>')]). lam, lam_late and the 8M sensitivity of one contrast share the same draws. Two-level bootstrap: units with replacement, then runs with replacement inside each (start, arm) cell of every drawn copy. Percentiles use numpy's linear method on the resampled R.
- 'V2s misses counted at 8M' (A.11 NO-ROOM b): only the comparator's missed T become 8M, in lam. A missed M_{k_first} gives log(miss value) terms in lam_late, which is log(4M) in the primary analysis as written. A reached k_first with a missed later rung gives log max(5000, cap - T_first) (the literal reading).
- A run's T is computed from records+ladder (A.5). The 'T'/'T_total' fields are used only when a run has no records. A run with no T_total has total frames = T (0 oracle). For total emulated frames, a miss is set to cap + the run's oracle_frames (report only). R_total is reported for every instrument row.
- A unit enters a contrast when at least one (g, s) has |K_{g,s}| >= 2 and runs of both arms. The D control and the instrument line use the cross-fitted K_{g,s}, because A.8 defines lam on K_{g,s}. In the D control, a unit with no D run, or a D run without a non-empty, fully exact confirmation, counts as a failure. An instrument line that cannot be computed counts as INSTRUMENT-FAIL.
- I-stage 'stage' field is D-CONTROL-FAIL, not 'Interruption (D)', on a first failure. The dated fix and second-failure bookkeeping are left to the stage operator.
- Cross-fit (A.10.4): k_top = the minimum over the other start's V2s runs of each run's highest reached k in K_g. With fewer than 3 runs, all present runs must reach k, and the cell is flagged complete=false. A start that is valid in S0 but has no V2s runs gives k_top None, so cells relying on it are dropped. Without starts.json, a start is valid iff it has V2s runs.
- K*map MAP-WEAK: coverage is pooled as sum(found)/sum(coins) over the row's runs (fallback: mean of per-run coverage). Unknown coverage counts as MAP-WEAK, since it cannot establish 'not MAP-WEAK'. O-TIES is pooled as o_ties weighted by expansions_scored.
- Interruption: also raised for a missing dirty flag, a missing closure hash, or provenance.closure_consistent == false (segments of a resumed run under different code, treated as a mixed closure). For a reused arm (V2s) whose closure differs from the gate's committed one: a missing certificate gives 'missing comparator certificate', and a failed one gives 'all V2s runs must be redone'. Caption rows (O_4-dice, K*mac-exact) are reported without labels and kept out of the Interruption check.
- Certificate: compares records (json byte equality) and the exp_meta hash. It reads exp.meta_sha256 as written by v85_job, else exp_meta_sha256, else a hash of exp_meta. An absent hash fails the certificate. A start with no original I-stage run on the first unit (invalid start) is skipped.
- A.12: v_K = df-pooled within-(g, s) variance of lam(K) / that of V2s. tau_K = DerSimonian-Laird method-of-moments SD of the unclipped l_g, with within-unit variances built from the pooled variances. The rerun uses run noise variance max(0, v_K - 1) * sigma2_{g,s} and tau = tau_K at the frozen (n, tau_pt, tau_lb). It is only run when v_K > 1.5 or tau_K > 0.4 and the label is ROOM-K or NO-ROOM-K. A downgrade removes the BELOW-2X caption.
- Calibration resampling is in log T. Residual inflation is sqrt(m/(m-1)) for a cell with m runs, which equals the frozen sqrt(3/2) at the I-stage's m = 3. Cells with < 2 runs are refused. No monotonicity repair of resampled vectors. A base element is censored when its resampled T is at or above the cap (always so when drawn from a run that missed it).
- sigma2_{g,s} = sample variance (ddof 1) of the cell's V2s lam. eps is drawn once per planted run and applied to all its T. A 'stay' censored element stays exactly at the cap with no noise. Any planted T at or above the cap is a miss.
- Censoring treatment 'divide' plants the cap value as if it were observed (cap/D_eff for the D scenarios, first + (cap - first)/D_eff for D_late, 5000 + cap - T_first for D_jump). D_late divides the gaps after k_first by D_eff = 2*exp(tau z). D_jump gets no tau heterogeneity (it is fully specified).
- Treatment per criterion: 'stay' for (i), (vi), mean R(D2) and mean R_late(D_late). 'divide' for the false-ROOM rates (ii)-(v). (vii) P(NO-ROOM | D1) is listed under neither treatment, so it must hold under both (the minimum is used, conservative). Every operating characteristic is reported under both treatments, including P(NO-ROOM | D1.5).
- Per simulation b, the generator default_rng([9802, b]) draws once: the comparator, 3 base runs per (row, cell), z, eps and the bootstrap draws. These are shared across n (the first n/2 base runs are used), tau and scenarios (common random numbers). Per-row probabilities average the 3 exchangeable rows, and (iv) is any of the 3 rows at D1 under 'divide'. The same [9802, b] streams serve the S0 spike-ins and the A.12 rerun.
- Calibration outcome: SELECTED, or TOP-UP when nothing qualifies before the top-up (CLI `run`; rerun with `--topped-up` after the top-up), else UNDERPOWERED. `f1` refuses unless SELECTED. assemble_f1 applies the §13.1 O_4 rule only from a supplied budget['projection_frames'] (n_O4 = 4 above 0.6e9) and leaves hashes/closures/seed grep/budget as inputs.
- Arm names match case-insensitively with '*', '_', '-' and spaces ignored ('~' -> 'tilde'), so 'v2s', 'O_4', 'K*map', 'kmap', 'O_4-dice' all resolve. The regime ratio is reported as R(natural V2 from its own M1 : V2s from s1), with natural runs only for units whose v84 files exist. ssc_core was restructured (start-weighted unit means before pair differences, einsum). This is mathematically identical to the per-pair form and is checked against a naive loop in the tests.

Not done at build time (some fixed by the review, see §4):
- B1 sealed label ladder (NEGATIVE-TRANSFER ... NULL), with the permutation p <= 0.025, the leave-one-game-out minimum, ACCUMULATES (Page's L over doses 0/4/12/41) and the X4/X12 dose lines. Only the generic contrast() and the G2a/G2b label functions exist.
- G2b reports: phi = log R(X:F)/log R(K:F) helper, the family-M interaction I = [lam(X_frozen) - lam(X_on)] - [lam(V2s) - lam(F_M)] with its bootstrap interval, and the CENSORING-SENSITIVE 'label drops one step' rule for G2b/B1. The 8M sensitivity statistics (R_8M, UB95_8M) are provided by contrast().
- No CLI subcommands for G2a, G2b or B1. Pure functions g2a_label, g2b_label and vocab_caption exist.
- The §13.1 budget projection itself (cost from the I-stage mean V2s billed per run) is not computed here. assemble_f1 only applies the O_4 n=4 rule from a supplied projection.
- S0 items that belong to v85_stage0 (physics floor, G_4 dice prediction, stall inventory, seed grep) are not done. Only p_room_x2 is provided for A.10.1(c).

### instruments

- Q5 streams: first_slot draws one macro from P_{e,j} and returns only its first resolved slot, so propose stays side-effect free. At t=1, inside the rollout, the first macro is drawn again from X_e among the macros whose first slot is the slot played at t=0, with the same weights. The law is the same as drawing the macro from P. Later macros are drawn from X_e. The position inside the current macro is per-rollout state and is not in to_state, since checkpoints are taken at expansion boundaries.
- Q5 draw law: p = 0.9*count/total + 0.1/N. An unavailable slot falls back to its movement class without extra, then to NOOP. Q5 is placed in the agent package (agent_v85/q5_v85.py) because Part B item 12 puts the Q5 process agent-side; K*mac imports it so that K*mac and family M share one Q5.
- Bandit k: with an empty library k stays 4, so the run is byte-identical to V2s (G-build test 6). A fifth arm with zero counts is added at the first expansion boundary where the library is non-empty. This also covers F_M after its first mining. Before this change, explorer2s gave k=5 to any q5, which broke test 6.
- D: expansion 0's exp_meta row uses the (q, slot) drawn by propose(0, 0); the scripted rollout ignores them. d_script ends on the step that reaches M_{k_ref}. The first rollout therefore completes, and the stop then raises Spent at the next restore: exp_n == 1 and billed since clock == 60 + 4*len(script), as tested.
- K*mac windows: a rise at lineage step t gives the window t-31..t. A rise with t < 31 has no full window above s1 and is skipped; the count is reported as rises_without_window. A rise is cum[t] > cum[t-1], with cum[-1] = S(s1).
- K*mac 'round-trip fidelity' = share of the sampled actions a (window steps 0, 4, ..., 28) for which to_button(slot(a)) == a, after priv/unmapped -> NOOP. Also reported: fidelity_held (share of all 32 window steps whose held button equals the lineage action) and fidelity_slot (share whose slot survives). share_priv_or_noop counts the priv, unmapped and NOOP-class sampled steps whose final slot is NOOP.
- K*mac-exact: the same windows, every step's slot held 1 step. The priv slots of this start's own adapter are kept, since they are playable and exact; only unmapped actions go to NOOP.
- O_4 rank correlation: the executed outcome is scored with the same tuple as the look-ahead, using best_S from before the execution. Spearman is computed on the lexicographic ranks; it is None if fewer than 3 pairs or one side is constant.
- KMap.caption: MAP_WEAK is also True when coverage is undefined (no coin). This can only block NO-ROOM-K*map. It is consistent with arms_v85/kmap.py.
- K~mac: the derangement uses permutations of the given unit list (Ctx.units, in draw order), drawn from default_rng([9801, 2]) and redrawn until no unit is fixed, so it is uniform over derangements. The partner's library is taken at the same start label, else at the partner's other start, else empty (equal to V2s). The partner's K*mac row at start s requires both of its starts to be valid.
- O_4-dice frames: compared as the emulated-frame delta after the restore, in both the look-ahead and the execution (the restore costs 60 in both).

Not done at build time (some fixed by the review, see §4):
- No arm modules were written for D, O_4-dice, K*mac, K*mac-exact, GF4, GF or K~mac. ragnarok/evaluation/arms_v85/ is another agent's area; the wiring each one needs is listed under needs_from_others.
- No v85 isolation test file (G-build test 1) was written; it is not in my file list. I ran the rules ad hoc on agent_v85/*.py and they pass.

### run-infra

- Fields that may differ between two runs of the same (unit, start, arm, seed), interrupted or not (tests 4 and 5), are only wall_s, peak_ws_mb, peak_commit_mb and provenance. Checkpoint stats, per-process segments and the closure listing live inside provenance.
- Extra JSON fields beyond the shared schema: E, k_first, rungs_source ('f1' or 's0'), billed, stopped, s1_sha256, aborted, and exp = {n, meta_sha256, feat_sha256}. exp_meta and exp_feat go to a sidecar <OUT>.npz, written before OUT, because the §13.4 comparator certificate compares exp_meta byte for byte. Hashes are taken on the array bytes, since npz zip timestamps vary.
- T and T_total are recorded for every ladder rung k = 1..10 (null when missed), a superset of the counted rungs. The verdict selects the rungs it needs.
- Rungs: if f1_thresholds.json has K_gs[game][start], rungs = K_{g,s}; otherwise rungs = K_g. k_first = min(rungs); k_ref = max(K_g) always, so the evaluator stop is at M_{k_ref} (A.4).
- Replay confirmation covers the first record reaching M_{k_first}, the highest reached rung among the run's rungs, and the highest reached in K_g if higher. ok means cum is exactly equal (literal A.5). true and depth are recorded beside it but are not part of ok.
- The job's own rolling checkpoint is deleted after its JSON is written; --keep-ckpt keeps it. The §13.2 disk budget of about 12 GB with 'one rolling checkpoint per job' implies the deletion.
- closure_consistent: at each checkpoint write, the closure pairs imported so far are stored. Every earlier process segment must have the same commit, and its pairs must be a subset of the final closure, with no foreign modules. The closure hash itself is computed at run end, as in §13.4.
- Smoke start: built by the S0 procedure, start_v85.top_lineage on the v84 G1b reference logs 9712/9713, read as data only exactly as S0 does. Every new emulator or agent seed is 9800, and one entry cache is shared by both starts. Smoke K_g = every k in 2..k* with M_k above both S(s1): the 50k gap rule is skipped so that small caps cross rungs. --cap is accepted only with --smoke; non-smoke runs assert cap = 4M. Smoke asserts seed 9800.
- v85_job sets OMP_NUM_THREADS=2 by default (setdefault) before numpy is imported. Measured process commit after the imports was about 780 MB without it and 137 MB with it (§13.2 target is 0.7 GB per worker).
- o4.py and o1.py now use the instruments agent's OChooser.after and OChooser.caption() (O-TIES, rank correlation) instead of my own first implementation, so there is a single definition. They add oracle_frames and winner_counts.
- K*map: the map is rebuilt in-process per run, deterministically, on SenseEnv85(game, E_s). Its emulation is reported as instrument.map_frames (4 per lineage step), not as the run's oracle_frames, because the map is fixed per start. map_sha256 is reported for F1.
- Arm interface extensions so that v85_job.py never needs editing:
- 'kwargs' are passed through to Explorer2s (after=, script= for D and O_4-dice).
- An 'explorer' factory can replace Explorer2s.
- Stateful hook objects (the chooser, and any kwargs value with to_state) are checkpointed under 'hooks'.
- ABORTS, a tuple of exception classes: the run JSON is written with aborted=message and is not retried. This is for O_4-dice's 'a failure aborts the run (counted)'.
- Queue choices:
- O_4-dice 'even draw positions' read as the 0-based index in the A.2 order: the first unit gets start A. It is skipped if that start is invalid.
- K*mac-exact runs at every kept start, since it uses only its own lineage.
- K*mac runs only when the other start is valid.
- (g, s) is dropped when |K_{g,s}| < 2.
- D's agent seed is E_s.
- Queue choices, scheduling:
- TERMINATE is detected from a job exit code 3 (the supervisor's TerminateProcess code) or from new TERMINATE lines in craft_v6_out/ram_supervisor.log of both the worktree and F:\dev\ragnarok. Either one triggers a 25-minute back-off for all workers.
- Passes are unlimited; a pass that meets only failed jobs waits 10 min.
- The longest-first key is the S0 'ref_gap' if present, else the mean billed of finished I-stage V2s runs, else 1, multiplied by an arm cost factor (o4 x5, d x0.2).
- Workers default to 3 (at most 4). Jobs run with CREATE_NO_WINDOW, OMP_NUM_THREADS=2 and PYTHONHASHSEED=0.
- The smoke stage is breakout and pong, start A, seed 9800, cap 500k, for each arm file present.
- Kill tests (G-build test 5), each comparing the final JSON byte for byte apart from the volatile fields:
- a real TerminateProcess of a subprocess at a random moment (rng [9800, 50]);
- an in-process kill mid-rollout at a random expansion and step for K*map (rng [9800, 51]);

### stage0

- A.2 order: default_rng([9801, 1]).permutation of the 16 eligible units (start_v85.unit_order), with drops removed afterwards and the order kept (most literal reading of §12 and A.2: 'Eligible: the 16 units ... kept or dropped'). starts.json 'order' lists the units in that draw order, dropped units included, so the queue's O_4-dice parity uses true draw positions. 'kept' lists the kept units in that order; the first U are used.
- Entry cache: built only for starts that pass the top-lineage replay and start identity, since an invalid start is dropped and no arm loads its Body. Start identity runs before the entry. Both use fresh emulators, so the results are the same. The cached Body is loaded back with a hash check (body_loads). Bodies are keyed by (unit, E), so a test that uses the same E at both starts shares one file; in production E differs (9819/9820).
- K_g = [] for a unit with no valid start. A unit is kept iff it has a valid start and |K_g| >= 2. KC-start (< 10 kept units), KC-floor and U are labelled only once all 16 units are done. Before that they are null, and partial values are reported (U_partial, median_ratio). The queue's istage therefore refuses until S0 is complete.
- (b) The KC-floor median is over every valid start of the kept units. The median over the first U units is a caption. Ddepth is the number of lineage steps from s1 up to and including its first step with cum >= M_{k_ref}. The natural gap is T_r(M_{k_ref}) - T_r(M1) on that start's reference run (A = 9712, B = 9713).
- (c) Natural cells: each unit's two G1b runs (9712, 9713) form one 2-run base, placed at each of its valid starts. One run per (g, s) cannot be resampled with centred residuals, so this follows the design of 2 starts per unit. The calib's inflation is then sqrt(m/(m-1)) = sqrt(2) for m = 2. T(M_k) - T(M1) is floored at 5,000, the yardstick's own floor, so that a 0 gap stays finite in log T; lambda is unchanged by that. All candidate U in {10, 12, 16}, each capped at the number of kept units, are computed and reported. U is the smallest one with P >= 0.8. If none qualifies, U is the largest candidate and qualified = false. The table is cached when the cells hash, sims and B are unchanged.
- (d) A G1b record (a clone that raised the best cum) belongs to the expansion e whose billed span (end_{e-1}, end_e] contains it, using exp_meta column 4. A record after the last exp row belongs to the expansion cut by the cap. A segment is one reference run at a valid start of a kept unit: the expansions after the one that reached M1, up to and including the one that reached M_{k_ref}. A segment with no expansion has p = None and is skipped. The primary G_4 is the mean over the segments of the first U kept units.
